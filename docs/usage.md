# 使い方

## コマンド

| コマンド     | 説明                                                                 |
|--------------|----------------------------------------------------------------------|
| `tui`        | 時計を大きく表示する                                                 |
| `once`       | 1 回だけ問い合わせて結果を表示する（`--json` で JSON 形式）          |
| `stats`      | 一定間隔で問い合わせを続け、オフセットと遅延の統計を表示する         |
| `sim-server` | 開発用の疑似 NTP サーバ（`--snmp-mib` を付けると疑似 SNMP エージェントも起動） |
| `sim-ptp-master` | 開発用の疑似 PTP マスタ（`--ptp` を実機のマスタなしで試す）    |

サーバは `192.168.1.123`、`ntp.example.com`、`127.0.0.1:12300` のように指定する。ポートを省略すると 123 を使う。
`tui`・`once`・`stats` は、NTP サーバの代わりに ptp4l が合わせる NIC の時計（PHC）も表示できる
（[ptp4l が合わせる PHC の時刻](#ptp4l-が合わせる-phc-の時刻)）。PTP のスレーブとして、ネットワークの PTP マスタに
問い合わせることもできる（[PTP のマスタに問い合わせる](#ptp-のマスタに問い合わせる)）。
すべてのオプションは `ntpterminal <コマンド> --help` で確認できる。コマンドライン引数と設定ファイルの書き方、
全項目の一覧は [configuration.md](configuration.md) を参照。

### tui

画面には上から順に、見出し・サーバ名・時計・日付・状態・情報欄が並ぶ。

- **状態**: 最初は「応答待ち（未同期）」で、応答を受け取ると「同期済み」になる。応答が途絶えると
  「自走中（応答なし）」となり、最後に同期した時刻から時計を進め続ける（PC とサーバの時計の進み方の差を、
  それまでの測定から推定して補正する）。サーバに拒否された場合（KoD の DENY / RSTR）は
  「拒否された（KoD）」となり、問い合わせを停止する
- **情報欄**: オフセット、遅延、Stratum、Ref ID、NTP version、サーバ時刻、最終同期、次回取得、成功/試行、送信方式、
  タイムスタンプを表示する。オフセットと遅延には、直近の測定のうち遅延が小さく新しいもの（時計の基準に使っているもの）の値を使う。
  値が 1 ms 未満なら緑、10 ms 未満なら黄、それ以上なら赤で表示する
- **推移のグラフ**: `--trend` を付けると、情報欄の下にオフセットと遅延の推移を棒グラフで表示する。
  グラフを表示しても時計が小さくならない大きさの端末でのみ表示される（120×40 なら表示され、80×24 では表示されない）
- そのほか、`--interval-ms`（既定値 500）で問い合わせ間隔を、`--title` と `--footer` で画面上下の文言を、
  `--tz` と `--tz-label`（既定値は `+09:00` と `JST`）で表示するタイムゾーンを変更できる

### once

```console
$ ntpterminal once 127.0.0.1:12300
サーバ           127.0.0.1:12300
オフセット       -0.923 ms（サーバ − PC）
遅延             0.201 ms
Stratum          1
Ref ID           GNSS
NTP version      4
Leap             なし
Precision        2^-20 s
Root delay       0.000 ms
Root dispersion  0.244 ms
サーバ時刻       2026-11-16 (月) 21:29:26.662 JST
送信方式         UDP ソケット
タイムスタンプ   ユーザ空間
```

応答がない場合や、応答の内容が正しくない場合は、理由を表示して終了コード 1 で終了する。

### stats

```console
$ ntpterminal stats --count 5 --interval-ms 200 127.0.0.1:12300
127.0.0.1:12300 に 200 ms 間隔で問い合わせます（送信方式: UDP ソケット）
#1     offset   -0.916 ms  delay  0.215 ms  stratum 1  ref GNSS  同期済み
       状態: 未同期 → 同期済み
#2     offset   -0.968 ms  delay  0.117 ms  stratum 1  ref GNSS  同期済み
#3     offset   -0.957 ms  delay  0.164 ms  stratum 1  ref GNSS  同期済み
#4     offset   -0.969 ms  delay  0.113 ms  stratum 1  ref GNSS  同期済み
#5     offset   -0.961 ms  delay  0.137 ms  stratum 1  ref GNSS  同期済み
--- 127.0.0.1:12300 の統計 ---
成功/試行       5/5 (100.0%)  タイムアウト 0  通信エラー 0  不正応答 0  無関係 0
状態            同期済み
タイムスタンプ  ユーザ空間
offset [ms]     min -0.969  avg -0.954  max -0.916  σ 0.022
delay [ms]      min 0.113  avg 0.149  max 0.215  σ 0.042
採用値          offset -0.969 ms / delay 0.113 ms（直近で遅延と古さから選んだ標本）
周波数のずれ    推定前（1 分以上の測定が必要）
```

`--count` の既定値は 20 である。`0` を指定すると止めるまで問い合わせを続け、20 回ごとに途中経過の統計を表示する。
1 分以上問い合わせを続けると、「周波数のずれ」に PC のモノトニック時計に対するサーバの時計の進みの推定値（ppm）が出る。
`tui` の時計はこの値で補正している。サーバの時刻が段差で変わる（時刻の修正・閏秒など）と、段差の後の 2 回目の応答で
「時刻の段差を検出」の行を出し、それまでの測定を捨てて新しい時刻に合わせる（1 回だけ外れた応答は使わない）。
`--json` を付けると、各イベントを 1 行 1 件の JSON で出力する。`"event"` には `sample`・`timeout`・`rejected`・
`state_changed`・`step_detected` などが入り、最後に `summary`（推定した周波数のずれ `frequency_ppm` を含む）を出力する。

### sim-server

実機の NTP サーバがなくても動作を確認できるよう、疑似 NTP サーバを起動する（既定では 127.0.0.1:12300 で待ち受ける）。
`--offset-ms` で PC の時計に対するずれを、`--stratum` と `--refid` で応答の内容を変えられる。
`--snmp-mib` を付けると、GNSS 受信機の値を返す疑似 SNMP エージェントも起動する。
確認の手順は [testing.md](testing.md) にまとめてある。

### sim-ptp-master

実機の PTP マスタがなくても `--ptp` を試せるよう、疑似 PTP マスタを起動する。Announce（1 秒ごと）・Sync・`Follow_Up` を
`--to`（既定: マルチキャストの 224.0.1.129）へ送り、`Delay_Req` に `Delay_Resp` で応える。時刻は「PC の時計 +
`--offset-ms`」で、何にも合わせていない時計（clockClass 248・時刻源は内部の発振器・UTC との差 37 秒）として知らせる
（疑似マスタを使った表示が、GNSS に合わせた時計に見えないように）。時刻はユーザ空間で読むので、
数十 µs の揺らぎがある。root なしで試すときは、1024 以上のポートとループバックのユニキャストを使う。

```sh
ntpterminal sim-ptp-master --port 12319 --to 127.0.0.1:13319 --interface 127.0.0.1 --offset-ms 2.5
ntpterminal tui --ptp --ptp-port 13319 --ptp-interface 127.0.0.1 --ptp-master 127.0.0.1:12319   # 別の端末で
```

LAN の別の PC から試すときは、マルチキャストで送る（`--to` を省略する）。このときは `--interface` のインターフェースで
マルチキャストのグループに参加し、全アドレスに bind して、マルチキャストの `Delay_Req` にも応える（Windows では
ファイアウォールの確認が出る）。ほかの機器が合わせてしまわないよう、既定でないドメイン番号を使う。

```sh
sudo ntpterminal sim-ptp-master --interface 192.168.1.10 --domain 99
ntpterminal tui --ptp --ptp-domain 99 --ptp-interface 192.168.1.20   # LAN の別の PC で
```

## 送信方式とタイムスタンプ

OS によって使える方式が異なる。

|                | Linux                                   | Windows         |
|----------------|-----------------------------------------|-----------------|
| 送信方式       | `udp` / `raw-ip` / `link`               | `udp`           |
| タイムスタンプ | `auto` / `user` / `kernel` / `hardware` | `auto` / `user` |

| `--transport`   | 送信方法                                                 | 必要な環境・権限               |
|-----------------|----------------------------------------------------------|--------------------------------|
| `udp`（既定値） | OS の UDP ソケットを使う                                 | なし（すべての OS）            |
| `raw-ip`        | IPv4 / UDP ヘッダを自前で組み立て、raw ソケットで送る    | Linux、root または `CAP_NET_RAW` |
| `link`          | Ethernet フレームから自前で組み立て、`AF_PACKET` で送る  | Linux、root または `CAP_NET_RAW` |

- `raw-ip` と `link` は IPv4 のサーバにのみ対応する。`--ttl`、`--dscp`、`--no-df` などでヘッダの値を変更できる。
  `link` ではさらに、宛先 MAC アドレス（`--dst-mac`。省略すると近隣表または ARP で調べる）と、
  802.1Q の VLAN タグ（`--vlan`、`--pcp`）も指定できる
- 送信元 IP アドレスには、経路に応じた自ホストのアドレスを常に使う。送信元を偽装する機能はない
- 送信方式と組み合わせられないオプション（`udp` での `--dscp` など）を指定すると、無視せずにエラーとする

| `--timestamping` | 取得方法                                                                                   |
|------------------|--------------------------------------------------------------------------------------------|
| `auto`（既定値） | カーネルのタイムスタンプが使えれば使い、使えなければユーザ空間で時刻を読む                 |
| `user`           | ユーザ空間で時刻を読む                                                                     |
| `kernel`         | カーネルのタイムスタンプ（`SO_TIMESTAMPING`）を使う。Linux のみ                            |
| `hardware`       | NIC のハードウェアタイムスタンプを使う。Linux のみで root が必要。NIC 側で無効になっていれば一時的に有効にし、終了時に元の設定に戻す |

画面には、指定した方法ではなく実際に使えた方法を表示する。指定した方法でタイムスタンプを取得できなかった場合は、
その旨を情報欄の「タイムスタンプ」に表示する（例: `カーネル（ハードウェアの時刻が取れない）`）。
`hardware` を実機で確認する手順は [testing.md](testing.md#ハードウェアタイムスタンプnic-の時計) にある。

## GNSS 受信機の状態（SNMP）

`tui` に `--snmp-community <コミュニティ名>` を付けると、NTP サーバと同じホストに SNMP v2c で問い合わせ、
情報欄の「Ref ID」の下に「GNSS 受信機」と「衛星」の 2 行を追加する。

```sh
ntpterminal tui 192.168.1.123 --snmp-community public
```

対応している MIB は、Meinberg の MEINBERG-OS-MIB・MBG-SNMP-LTNG-MIB・MBG-SNMP-LT-MIB と、
Microchip SyncServer S650 の MIB である。既定（`--snmp-mib auto`）では、応答のあった MIB を自動で選ぶ。
衛星数の数え方（受信良好・可視・追尾中など）はメーカーによって異なるため、種類ごとに分けて表示する。
MIB ごとの対応は [acl/mib.rs](../crates/application/src/acl/mib.rs) の先頭にまとめてある。
疑似 SNMP エージェントで試す手順は [testing.md](testing.md#gnss-受信機の行snmpを確かめる) を参照。

## ptp4l が合わせる PHC の時刻

`--ptp4l` を付けると、NTP サーバの代わりに、ptp4l（linuxptp）が PTP で合わせている NIC の時計（PHC）の時刻を表示する。
Linux のみで、root 権限が必要（PHC の `/dev/ptpN` と、ptp4l の管理用ソケットを使うため）。ptp4l は同じホストで、
ハードウェアのタイムスタンプを使って動いていること。

```sh
sudo ntpterminal tui --ptp4l
sudo ntpterminal once --ptp4l --ptp-domain 24
sudo ntpterminal stats --ptp4l --count 0 --ptp4l-socket /var/run/ptp4l
```

- ptp4l の状態は、ptp4l の管理用ソケット（`pmc -u` と同じ）で読む。場所は既定では `/var/run/ptp/ptp4l`、
  なければ `/var/run/ptp4l` で、ほかの場所なら `--ptp4l-socket` で指定する。読み取り専用のソケット
  （`uds_ro_address`）は、ポートの一覧に答えないので使えない
- ptp4l は、ドメイン番号が自分の設定と違う問い合わせに答えない。0 以外なら `--ptp-domain` で指定する。
  gPTP の設定（`transportSpecific 1`）の ptp4l には対応していない
- 問い合わせは ptp4l の中だけで処理させ、ネットワークへは転送させない（`pmc` の `-b 0` と同じ）
- ptp4l と同じネットワーク名前空間で動かす（コンテナなどで名前空間が違うと、ptp4l の応答が届かない）
- 表示する PHC は、ptp4l が知らせるもの（仮想 PHC を含む）を使う。ptp4l が複数の PHC を使うときだけ、
  `--phc /dev/ptp1` か `--phc eth1`（ポートのインターフェース名）で選ぶ。ptp4l が PHC を合わせていないときは
  エラーになる: ソフトウェアのタイムスタンプ（`-S`）か従来の方式のハードウェアのタイムスタンプ（`-L`）で動いている
  （ptp4l はシステムの時計を合わせる）か、`free_running 1`（ptp4l は PHC の番号を -1 と知らせる）のとき
- PHC の時刻は PTP の時刻系（TAI）なので、ptp4l が知らせる UTC との差（currentUtcOffset、いまは 37 秒）を引いて
  表示する。グランドマスタがその値を確かなものとして知らせていなければ、情報欄に「（未確定）」と出す。
  時刻系が ARB（任意）なら換算せずにそのまま表示する
- `--transport` などの送信方式の指定・`--snmp-*`・`--allow-fast-poll` とサーバの指定は、一緒に使えない（エラーになる）

### 状態と時計

PHC だけでは同期しているかどうか分からないので、ptp4l のポートの状態で決める。
ptp4l が同期を知らせるまでは、大きい時計は `--:--:--.---` のままにする（合わせられていない PHC は任意の時刻で進む）。

| 状態の表示                         | ptp4l のポートの状態                  | 時計                     |
|------------------------------------|---------------------------------------|--------------------------|
| ptp4l の応答待ち / ptp4l の応答なし | （まだ読めていない）                  | 出さない                 |
| マスタを探しています               | LISTENING・INITIALIZING・PASSIVE など | 出さない                 |
| マスタに合わせています             | UNCALIBRATED                          | 出さない                 |
| 同期済み                           | SLAVE（どれかのポート）               | 出す                     |
| マスタとして動作中                 | MASTER・GRAND_MASTER                  | 出す（この PHC が基準）  |
| 自走中                             | 一度同期した後に上のどれでもなくなった・ptp4l の応答がない | 出し続ける |
| ポートが使えません                 | FAULTY・DISABLED                      | 出さない                 |

自走中は、ptp4l が最後に合わせた速さで進む PHC をそのまま読み続ける。ptp4l の応答がなくても PHC は読み続け、
最後に読めた UTC との差で換算する。

### 情報欄

マスタとの差（ptp4l の offsetFromMaster）・経路遅延（meanPathDelay）・グランドマスタ・Clock class・時刻源・
UTC との差・うるう秒・PC との差（PHC − PC。PC の時計の合い方の確認用）・ポート・PHC・最終取得・成功/試行を表示する。
マスタとの差は、1 µs 未満なら緑、100 µs 未満なら黄、それ以上なら赤で表示する。`--trend` を付けると、
推移のグラフにはマスタとの差と経路遅延を出す。

`once --ptp4l` は 1 回読んだ結果を出し、ptp4l が同期を知らせていなければ（時計を出さない状態なら）読めても
終了コード 1 で終わる。`stats --ptp4l` は読むたびに PC との差・マスタとの差・経路遅延を出し、最後に統計を出す。

## PTP のマスタに問い合わせる

`--ptp` を付けると、NTP サーバの代わりに、PTP（IEEE 1588）のスレーブとしてネットワークの PTP マスタに問い合わせ、
マスタの時刻を表示する。PC の時計は合わせない（NTP と同じく、測った時刻を表示するだけ）。対応しているのは
既定のプロファイル（UDP/IPv4・E2E。one-step と two-step のマスタ）で、L2（Ethernet）・P2P（Pdelay）・
ユニキャストのネゴシエーション・gPTP（`transportSpecific 1`）には対応していない。

```sh
sudo ntpterminal tui --ptp --ptp-interface eth0
sudo ntpterminal once --ptp --ptp-domain 24 --timestamping kernel
sudo ntpterminal stats --ptp --ptp-master 192.168.1.50 --count 0
```

- UDP の 319 番（イベント用）と 320 番（一般用）を使う。1024 未満なので、Linux では root か
  `CAP_NET_BIND_SERVICE` が必要（`--ptp-port` で別の番号にもできるが、マスタも同じ番号で送る必要がある）。
  `SO_REUSEADDR` を付けるので、同じホストで ptp4l が動いていても使える（マルチキャストは両方に届く。
  ユニキャストの `Delay_Resp` はどちらか一方にしか届かないことがあるので、その場合は `--ptp-master` を付けない）
- マルチキャストのグループ 224.0.1.129 に、`--ptp-interface` のインターフェース（名前か IPv4 アドレス。
  名前は Linux のみ）で参加する。省略すると、マスタ（`--ptp-master`）かマルチキャストのグループへの経路で決める
- マスタは Announce で選ぶ。同じ送り手から Announce が間隔 4 回分の中に 2 通届いたら候補にし、priority1・
  clockClass・精度・priority2・グランドマスタ・stepsRemoved の順に良いものを選ぶ（BMCA を簡略にしたもの）。
  Announce が間隔 3 回分届かなければ見失ったとする。既定のプロファイルは Announce が 2 秒ごとなので、
  選ぶまでに数秒かかる（`once --ptp` の待ち時間の既定は 10 秒）
- 選んだマスタの Sync を受け取ったら、すぐに `Delay_Req` を送り、`Delay_Resp` でマスタが受け取った時刻を知る。
  Sync の送信（two-step なら `Follow_Up` の時刻）・受信、`Delay_Req` の送信・マスタの受信の 4 つの時刻と、
  経路の機器が足した補正（correctionField）から、マスタと PC の差と往復の遅延を求める。式は NTP と同じで、
  基準点は Sync を受け取った瞬間にする
- `Delay_Req` は、`--interval-ms`（既定 500 ms）とマスタの最小間隔（`Delay_Resp` の logMessageInterval。
  知らされるまでは既定のプロファイルの 1 秒）の長い方の間隔で送る。マスタの最小間隔より短くは送らない。
  情報欄の「間隔」に、実際の間隔と、それがマスタの最小間隔によるものかを出す
- 既定では `Delay_Req` をマルチキャストで送る（既定のプロファイルどおり。ほかのスレーブにも届く）。
  `--ptp-master` を付けると、そのアドレスへユニキャストで送り、マスタはユニキャストで応える（ptp4l の hybrid E2E と同じ）
- 自分のポートの識別子は、起動のたびに乱数で作る（ローカルに割り当てたアドレスの EUI-64）。NIC の MAC から
  作らないのは、同じ NIC で動く ptp4l と同じ識別子になり、互いの `Delay_Resp` を取り違えないようにするため
- ドメイン番号が違うメッセージは使わない。マスタが見つからないときに、ほかのドメインのメッセージが届いていれば、
  そのドメイン番号を知らせる（`--ptp-domain` で指定する）
- マスタの時刻は PTP の時刻系（TAI）なので、Announce の UTC との差（currentUtcOffset）を引いて表示する。
  時刻系が ARB（任意）なら換算しない（ソフトウェアのタイムスタンプで動く ptp4l は ARB で UTC をそのまま送る）
- タイムスタンプ（`--timestamping`）は `user`・`kernel`・`auto` が使える。カーネルの時刻は、Sync の受信と
  `Delay_Req` の送信の両方で取れたときだけ使い、片方しか取れなければ両方ともユーザ空間の時刻にする（片方だけ違うと
  差が偏る）。実際に使えた方式は情報欄と `once`・`stats` の出力に出す。NIC のハードウェアのタイムスタンプ（`hardware`）には
  まだ対応していない（エラーになる）
- サーバ・`--timestamping` 以外の送信方式の指定・`--snmp-*`・`--allow-fast-poll`・`--ptp4l` とは一緒に使えない（エラーになる）

### 状態と時計（--ptp）

| 状態の表示                       | 意味                                                         | 時計       |
|----------------------------------|--------------------------------------------------------------|------------|
| マスタを探しています（ドメイン N） | 候補になるマスタがいない                                    | 出さない   |
| マスタの時刻を測っています       | マスタを選び、最初の交換を待っている（失敗の理由があれば添える） | 出さない   |
| 同期済み                         | マスタの時刻を測れている                                     | 出す       |
| 自走中                           | 測れていたが、マスタを見失った・測れなくなった               | 出し続ける |

自走中は、最後の基準点から PC のモノトニック時計で進め続ける（NTP の自走と同じ）。マスタが替わっても基準点は
捨てない。同じグランドマスタなら時刻は続いているはずで、違えば時刻の段差として検出して合わせ直す。

### 情報欄（--ptp）

PC との差（マスタ − PC）・経路遅延（片道）・マスタ（ポートの識別子とアドレス）・グランドマスタ・Clock class・時刻源・
UTC との差・うるう秒・間隔（Sync と `Delay_Req`）・最終取得・成功/試行・送受信・タイムスタンプを表示する。
`--trend` を付けると、推移のグラフには PC との差と経路遅延を出す。

`once --ptp` はマスタを選んで最初の交換で測った結果を出し、測れなければ理由（マスタが見つからない・応答がない
など）を出して終了コード 1 で終わる。`stats --ptp` は交換ごとに PC との差と経路遅延を出し、最後に統計を出す。
`--count` は交換の回数で、マスタが 30 秒見つからなければ終わる（終了コード 1）。

## 公開 NTP サーバでは使わないこと

1 秒未満の間隔での問い合わせは、自分で管理しているサーバに対してのみ行うことを想定している。
公開サーバに短い間隔で問い合わせると迷惑になるうえ、KoD（RATE / DENY）を返されることもある。
このため、プライベート・ループバック・リンクローカル以外のアドレスに対して 16 秒未満の間隔を指定すると、
`tui` と `stats` はエラーで終了する。自分で管理しているサーバがグローバルアドレスにある場合に限り、
`--allow-fast-poll` でこの制限を解除できる。
